What Data Goes In

Five input types an inspector can capture during a site visit

✍️ Typed Text Notes
Free-form observations per location — written directly in the app. Each note attaches to a specific area of the inspection.
🎙️ Voice Memos
Recorded on-site and auto-transcribed by Gemini via the /transcribe endpoint. Hands-free note-taking while walking the property.
📷 Photos
Up to 8 MB each, compressed at quality 0.6 (EXIF stripped). AI can auto-describe each photo to generate a caption for the report.
🎥 Video Clips
Up to 2 minutes / 40 MB. The primary evidence source — Gemini watches the full clip and identifies the best evidence frames.
🗂️ Project Metadata
Project name, inspection date, inspector name, case number, insurance company, address — all flow directly into the report template.

Offline-First Sync Pipeline

Data is never lost, even without connectivity

  • All writes go to local device storage first (AsyncStorage) — the app works fully offline
  • A background sync loop pushes changes to the Express API when connectivity returns
  • Last-write-wins merge resolves conflicts when the same project is edited on multiple devices
  • Pending-delete queue prevents a deleted project from coming back after a pull from the server
  • Media is deduplicated by URI — the same photo or video is never uploaded twice
  • 50 MB pre-flight check rejects oversized files client-side before any network call is made
Sync States
Synced — all data on server
Syncing — push in progress
Offline — queued locally
Disabled — no DB / no token
Debounced push
Changes are batched with a 2-second debounce to avoid flooding the API on rapid edits.

Media Processing — Getting to Gemini

Step-by-step journey from device to AI engine

  1. 1
    Inspector records video / takes photo on device — stored locally as a blob URI or file path.
  2. 2
    App fetches the local blob and pre-flight checks size — files over 50 MB are quarantined immediately with an amber warning banner. No network round-trip needed.
  3. 3
    Blob is POSTed to Express API → /api/media — multer enforces a 50 MB server-side cap; disk-full guard rejects at 90% capacity.
  4. 4
    Server saves file to persistent disk and records metadata in Postgres — returns a UUID media ID ({ id }). ID is stored back into the project locally.
  5. 5
    Express API builds a signed URL for the AI Engine — /api/media/<id>?token=… The token is embedded in the query string because media players cannot set custom headers.
  6. 6
    URL is handed to the AI Engine — the engine validates it (SSRF guard: scheme, path pattern, host pinning), downloads the file, then uploads it to the Gemini Files API for analysis.

From Analysis to Finished Document

Six steps from Gemini JSON to a shareable Google Doc

01

Gemini returns structured JSON

Area, source, cause, description, evidence timestamps, habitability, and repair recommendations — all validated against a typed schema.

02

Template placeholders filled

template_replacement.py replaces {{placeholders}} in the master Google Doc with Gemini's findings and the project's metadata.

03

Evidence frame extracted

OpenCV (cv2) seeks to Gemini's identified timestamp (ms) and reads the frame — the single best visual of the damage source.

04

Frame embedded in document

The evidence image is uploaded to Google Drive and inserted at {{damage.cause.picture}} in the report template.

05

Google Doc published

Google Docs API publishes the completed report to the output Google Drive folder. The doc is optionally shared directly with the inspector's email.

06

URL returned to app

The app receives a docs.google.com link. Inspector taps to open, or downloads as PDF / DOCX via the report proxy endpoint.

What Servers We Run

Three services, one Replit deployment

📱
Mobile App
Expo / React Native Web · Port 5000
  • Served as a progressive web app from the Expo dev server
  • TypeScript / React Native components — same code runs on iOS, Android & web
  • Zero extra hosting cost on Replit — runs on the same container
  • Offline-first local storage via AsyncStorage
Core
⚙️
Express API
Node.js · Port 3000
  • Project CRUD — /api/projects with PostgreSQL persistence
  • Media upload / download — /api/media with multer (50 MB cap)
  • Transcription & image description proxy → Gemini 2.0 Flash
  • Rate limiting: 300 req / 15 min general; 30 req / 15 min heavy endpoints
  • Admin dashboard, logs endpoint, disk-space guard
🤖
AI Engine
Python / FastAPI
  • Calls Gemini Files API — uploads video & photos for multimodal analysis
  • Calls Google Docs & Drive API — creates report, inserts evidence frame
  • Runs OpenCV (cv2) to extract evidence frames at Gemini timestamps
  • The only compute-heavy service — the main cost driver per inspection
  • SSRF guard on all inbound media URLs

Security & Reliability

Built-in safeguards across the full stack

🔑

Token authentication

x-tester-token required on all project and AI endpoints. Validated against the database (or env-var fallback) using constant-time comparison to prevent timing attacks.

🚦

Rate limiting

Two tiers: 300 req / 15 min globally; 30 req / 15 min on heavy endpoints (transcription, image description, report generation). Returns HTTP 429 on breach.

🛡️

SSRF protection

The AI Engine validates every inbound media URL: scheme must be http/https, path must match /api/media/<id>, and host must match API_BASE_URL when configured.

📦

Upload size enforcement

Client-side pre-flight rejects blobs over 50 MB before any network call. Server-side multer enforces the same cap and returns a structured FILE_TOO_LARGE error code.

💾

Disk-full guard

The media route checks disk usage before accepting any upload. At ≥90% capacity it rejects with HTTP 507 and a user-friendly message telling the inspector their data is safe on-device.

📶

Offline resilience

Pending deletes are persisted to AsyncStorage so a deleted project can never be resurrected by a pull from the server, even after a long offline period.

📋

Anonymous log writes

Client-side errors and actions are logged to /api/logs without requiring a valid token — enabling debugging of auth failures without exposing inspector PII.
